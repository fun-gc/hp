# 入部フォームと Discord 招待メールを設定する

運営メンバー向けの手順です。Google フォームが回答を受け付け、Google Apps Script が `@fun.ac.jp` のアドレスだけに招待メールを送ります。サイトはフォームへのリンクを表示します。

初回は「自動返信を有効にする」「公開前に送信を確認する」の順に進めてください。招待先の変更や送信失敗への対応は、その都度該当する項目を参照します。

## 自動返信を有効にする

1. 管理する Google アカウントで入部希望フォームを開き、「その他 → Apps Script」を選びます。
2. `bot/join/Code.gs` をエディターに貼り付けて保存します。
3. プロジェクトの設定でマニフェストの表示を有効にし、`appsscript.json` に `bot/join/appsscript.json` の内容を設定します。対象フォームの編集・メール送信・トリガー管理に権限を絞っています。
4. 同じ設定画面の「スクリプト プロパティ」に、名前を `DISCORD_INVITE_URL`、値をサーバーの招待 URL として追加します。招待 URL はリポジトリに書き込みません。
5. `installJoinAutomation` を選んで実行し、Google の権限確認を管理者本人が確認して許可します。
6. 実行ログの「自動返信の設定が完了しました」を確認します。左の「トリガー」には、`onJoinFormSubmit` の「フォーム送信時」が 1 件表示されます。

フォームには次の質問を用意してください。スクリプトはメール欄と確認欄の ID を保存するため、公開後にこの 2 問を作り直した場合は `installJoinAutomation` を再実行します。

| 質問 | 形式 | 必須 |
| --- | --- | --- |
| 氏名・呼ばれたい名前 | 記述式（短文） | はい |
| メールアドレス | 記述式（短文） | はい |
| 学年（任意） | 記述式（短文） | いいえ |
| 質問・相談（任意） | 段落 | いいえ |
| 回答内容の利用と自動送信について | チェックボックス | はい |

設定処理がメール欄の形式チェック、確認欄の選択肢、送信後の案内文を設定します。確認欄の文章を変更する場合は、`JOIN_CONSENT_TEXT` も合わせて変更してください。

メールはトリガーを作成した Google アカウントから送信されます。返信先は `contact@fungc.org` です。担当者を交代するときは、旧担当者のトリガーを停止し、新担当者のアカウントで設定を実行してください。

## 公開前に送信を確認する

フォームの説明に「`@fun.ac.jp` の場合、学内メール宛てに Discord 招待リンクを自動送信する」「学外には自動送信しない」「回答は入部・見学の連絡と参加案内に使う」と記載します。招待 URL 自体は説明や送信完了画面に載せません。

1. Google フォームを公開し、管理者自身の学内アドレスで実際に回答します。受信したメールから、目的の Discord サーバーを開けるか確認します。
2. 管理者自身の学外アドレスでも回答し、招待メールが送信されないことと、Apps Script の実行が正常終了することを確認します。
3. フォームの回答概要を一般公開しないこと、回答の編集を許可しないことを確認します。回答データは運営メンバーだけが閲覧できる状態にしてください。
4. 回答者向け URL を `src/lib/site.ts` の `joinFormUrl` に設定します。問い合わせ用の `contactFormUrl` は別設定です。
5. ホームページの変更をプレビューで確認し、運営メンバーのレビュー後に公開します。

自動送信は入力先のメールボックスを本人が受信できることを前提にしています。入力だけで在籍を認証するものではなく、ほかの人の学内アドレスを入力される可能性は残ります。招待リンクを転送すると第三者も参加できるため、Discord 側の参加ルールも利用してください。

## 招待先を変える

Apps Script のスクリプトプロパティ `DISCORD_INVITE_URL` を変更します。サイトの再ビルドは不要です。招待の期限・使用回数は Discord 側の設定で決まるため、運用中のリンクが利用可能か定期的に確認してください。

## メールが届かないとき

まず Apps Script の「実行数」で失敗した処理を確認します。メール送信には Google の日次上限があり、上限超過や一時エラーでは送信済みとして記録しません。

対象の回答 ID をスクリプトプロパティ `JOIN_RETRY_RESPONSE_ID` に入れ、原因を解消してから `retryJoinInvite` を実行すると、その回答だけ再処理します。回答 ID はフォームの回答を `FormApp.getActiveForm().getResponses()` で取得し、回答日時と照合して `getId()` で確認します。同じ回答を再処理しても、送信済みの記録があれば送信しません。

送信成功から記録までの間に処理が中断した場合は、再送で重複する可能性があります。再送前に送信履歴も確認してください。送信記録は回答 ID と日時のみをスクリプトプロパティに保存します。長期運用で保存容量に近づいた場合は、古い記録を別途保管してから整理してください。記録を消した回答を再処理すると再送されます。

設定に不明点がある場合は、フォーム管理者へ連絡してください。応募者からの連絡先は `contact@fungc.org` です。

## 用語と参照先

- **Apps Script**: Google フォームの送信に応じてメールを送るプログラムです。
- **トリガー**: フォームが送信されたときにプログラムを動かす設定です。
- **スクリプトプロパティ**: 招待 URL や送信済みの回答 ID を保管する、管理者向けの設定領域です。

Google 公式資料: [フォーム送信時のトリガー](https://developers.google.com/apps-script/guides/triggers/installable)、[MailApp](https://developers.google.com/apps-script/reference/mail/mail-app)、[送信上限](https://developers.google.com/apps-script/guides/services/quotas)。
